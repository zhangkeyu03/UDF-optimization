# ✅ Оптимизация функции F_WORKS_LIST

## 🔍 Описание проблемы

Изначально функция dbo.F_WORKS_LIST содержала следующие проблемы:

Использование двух UDF (F_WORKITEMS_COUNT_BY_ID_WORK), вызываемых по каждой строке, что приводило к 50 000 × 2 = 100 000 вызовам UDF.

Использование функции F_EMPLOYEE_FULLNAME, вызываемой по каждой строке.

ORDER BY внутри функции нарушает SQL стандарты для табличных функций и не влияет на результат.

💥 Результат: выполнение запроса SELECT TOP 3000 * FROM dbo.F_WORKS_LIST() занимало более 9 секунд.


# 💡 Предложенное решение
Была реализована новая версия функции F_WORKS_LIST_v2, в которой:

Подсчёты выполненных и невыполненных элементов заказа вынесены в CTE с агрегацией по WorkItem.

ФИО сотрудника собирается один раз через EmployeeNames CTE.

Удалено ORDER BY из тела функции, и используется на стороне запроса.

Устранены вызовы dbo.F_WORKITEMS_COUNT_BY_ID_WORK и dbo.F_EMPLOYEE_FULLNAME.

# 🚀 Результаты после оптимизации
SELECT TOP 3000 * FROM dbo.F_WORKS_LIST_v2() ORDER BY ID_WORK DESC;
Выполнение: ~200 мс

CPU время: ~141 мс

Кол-во возвращаемых строк: 3000

Соответствует заданию: ✅ Да

# 🤖 Использование LLM
Для анализа производительности и переписывания функции использовалась LLM (ChatGPT-4.5 by OpenAI). Основные промты:

“Оптимизируй табличную функцию, в которой вызываются UDF на каждую строку”

“Убери вызовы UDF и вынеси в CTE”
